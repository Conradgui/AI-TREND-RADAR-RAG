## 唯一管理循环

目标 → 当前事实 → 最小变更 → 产品/工程证据 → Gate 决定。

1. 开始只读本页、当前计划和相关 spec/差异；不反复读取全部历史。
2. 一次完成一个可用的产品能力，内部小步骤不逐个请求确认；每批最多一个写入者。
3. 先复用已有实现；新通用依赖只有在明确瓶颈、比较维护成本后才选，安装按用户权限要求办理。
4. 先小样验证，再扩展；目标测试完成且无新增风险就停止加测，不用测试数量当进度。
5. 同一根因两轮无新证据就停止盲试。阻塞当前主路径则诊断/求助，不阻塞则登记，不能把数据损坏、安全或错误引用降为“可忽略”。
6. Gate 只写一份执行记录，含版本、原始证据链接、失败、决定、下一步；本页只链接它。不建立新看板服务、常驻监工或调度框架。
7. 已批准范围内持续推进；到阶段关口简报。权限、真实成本、语料解冻、破坏性操作、产品取舍变化需单独确认。会话不运行时不声称仍在后台开发。

## 产品优先验收

先问：用户能完成什么？然后查：相关性/可信引用 → 可恢复性 → 延迟和成本 → 维护性。
代码全绿不能代替浏览器主路径和真实输出；允许证据不足，但不能用安全拒答掩盖本来可以回答的失败。
产品阻塞、安全/数据完整性是硬关口；纯样式、命名或未来架构美化不阻塞当前交付。

## 模型与质量复核

主会话按用户要求 medium；Sol 负责重大架构/规范，Luna Max 执行清晰文件范围，Terra 在阶段 Gate 只读复核产品、方向、证据和工程质量。
