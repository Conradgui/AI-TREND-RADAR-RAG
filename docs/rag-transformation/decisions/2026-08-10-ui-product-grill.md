# UI 产品决策 Grill 记录

> 日期：2026-08-10
> 状态：进行中
> 适用范围：Stage 4 UI 信息架构、交互与视觉重构
> 规则：每次只确认一个产品决策；在共享理解达成前不进入生产实现。

## 决策 1：首页主任务

### 已确认选择

**A：趋势研究工作台。**

用户打开首页后的核心任务不是从头阅读一份日报，也不是立即进入空白 Agent 对话，而是完成一条连续路径：

1. 快速发现当前值得关注的趋势；
2. 搜索并定位到具体新闻或选题条目；
3. 查看条目的来源、摘要和关联证据；
4. 在已有上下文基础上让 Agent 继续分析。

### 产品含义

- 日报保留为内容载体和证据集合，但不再等同于首页的信息架构。
- 条目级搜索是主流程，不再只是日期过滤器。
- Agent 是深入分析环节，不应以空白聊天框取代趋势发现。
- 首页应优先呈现“现在发生了什么、为什么值得关注、证据在哪里”，完整表格作为后续浏览层。

### 证据边界

- **用户明确选择**：趋势研究工作台。
- **现有实现事实**：当前首页仍以整份日报和宽表格为中心，站内搜索只聚焦日期，尚未实现上述路径。
- **AI 架构推导**：后续 UI、Search Document、条目深链和 Agent 上下文传递应共同围绕该主任务设计。

## 决策 2：首页首屏信息层级

### 已确认选择

**A：今日趋势摘要 + 3–5 张重点趋势卡片。**

首屏先帮助用户建立“今天值得关注什么”的整体认知，再允许用户进入具体条目和完整选题池。搜索仍是核心能力，但不以空白搜索框取代趋势发现。

### 产品含义

- 首屏不是宽表格，也不是纯搜索页或纯数据仪表盘。
- 重点卡片必须说明“发生了什么、为什么值得关注、证据来自哪里”。
- 完整选题表格保留，但位于首屏之后，作为系统性浏览和核查层。
- 趋势图表只能在指标口径可靠后按具体问题引入，不为了视觉效果提前堆叠。

### 证据边界

- **用户明确选择**：首屏采用今日摘要和重点趋势卡片。
- **AI 产品判断**：这种层级最适合“先发现，再定位，再分析”的主路径。
- **待验证假设**：3–5 张卡片能否覆盖用户每日决策所需的信息量，后续应通过可用性测试验证。

## 决策 3：趋势卡片的产品语义

### 已确认选择

**A：经过聚合验证的趋势主题。**

趋势卡片不等同于单条高分新闻。每张趋势卡片原则上应由至少两条相互支持的内容信号构成，并展示时间范围、来源数量和代表性条目。只有一条可靠证据时，应标为“新兴信号”，不能直接表述为已形成的趋势。

### 产品含义

- 热度分数不能单独决定“趋势”身份。
- Graph RAG 的主要产品价值之一，是连接同一主题下跨时间、跨来源的信号。
- 趋势聚合必须保留底层条目证据，用户可以反向核查结论。
- UI 必须明确区分“趋势主题”“新兴信号”和“单条新闻”，避免视觉样式造成语义混淆。

### 证据边界

- **用户明确选择**：首页卡片代表聚合趋势。
- **AI 约束推导**：两条证据是最低产品门槛，不等同于统计学显著性；来源独立性、时间跨度和内容一致性仍需进入评分规则。
- **待验证假设**：当前语料和图谱关系是否足以稳定生成 3–5 个合格趋势，必须通过离线评估确认，不能默认成立。

## 决策 4：趋势卡片点击后的主落点

### 已确认选择

**A：趋势详情视图。**

详情视图用于解释“为什么这些信号共同构成一个趋势”，展示趋势结论、时间线、代表条目、来源证据和相关实体，并允许用户带着当前趋势上下文继续询问 Agent。

### 产品含义

- 每条底层证据都必须能精确跳转到日报中的对应词条，而不是只打开日报首页。
- 外部来源链接与站内证据链接并存，用户可以核查原文。
- Agent 接收到的是当前趋势及其证据上下文，不要求用户重新描述问题。
- 详情视图必须具备稳定深链和明确返回路径。

### 暂不锁死的实现选择

- 桌面端采用侧边详情、浮层还是独立页面，留到原型可用性测试决定。
- 移动端可以采用不同容器，但必须共享同一详情数据合同和 URL 语义。

## 决策 5：全局搜索的默认范围

### 已确认选择

**A：默认搜索全部历史语料，并提供范围筛选。**

用户使用一个统一搜索入口查找具体条目、趋势、实体和来源，再通过最近 7 天、最近 30 天、当前日报、来源和类别等条件缩小范围。

### 产品含义

- 搜索结果粒度必须是具体条目或趋势，不能继续以“匹配日期”作为主要结果。
- `Open AI`、`openai` 等写法应先规范化并映射到 `OpenAI`，同时允许用户纠正系统判断。
- 当前日报搜索属于全局搜索的一个范围条件，不另设第二个竞争入口。
- 每个条目结果必须具备稳定深链，点击后直接定位到对应内容。

### 证据边界

- **用户明确选择**：统一全库搜索入口。
- **现有实现事实**：当前 Web UI 会下载日报并按日期过滤，没有条目级结果和深链。
- **AI 架构推导**：需要共享 Search Document、实体别名表、条目级索引和稳定 `occurrence_id`。

## 决策 6：搜索结果的信息结构

### 已确认选择

**A：分层结果，并解释模糊词识别。**

搜索结果顶部先展示系统对查询的规范化理解，例如“已将 `Open AI` 识别为 `OpenAI`”；随后按直接匹配实体或主题、相关趋势、具体新闻与选题条目分层展示。

### 产品含义

- 每条结果应显示匹配原因，例如标题命中、实体别名、摘要相关或趋势关联。
- 用户必须能纠正实体识别结果，避免一次错误消歧污染整个结果页。
- Agent 总结只能作为可选增强，不能替代底层召回结果和证据列表。
- 相关性排序需要可评估，不能只依赖模型生成的解释文案。

### 证据边界

- **用户明确选择**：透明、分层的搜索结果。
- **AI 产品判断**：该结构能同时支持模糊查询、纠错和证据核查。
- **待验证假设**：结果分层是否增加理解成本，需要在原型测试中观察首次使用者能否快速区分实体、趋势和条目。

## 决策 7：Agent 的角色与入口

### 已确认选择

**A：常驻的上下文研究助手。**

页面顶部保留明显的 Agent 入口，打开后进入可调整宽度的统一侧边面板。趋势卡片、搜索结果和具体条目均可通过“询问 Agent”将当前对象及其证据带入同一会话。

### 产品含义

- Agent 足够醒目，但不取代首页的趋势发现主任务。
- 用户不需要复制标题、摘要和来源重新描述上下文。
- 不为每张卡片建立独立对话，避免会话和状态碎片化。
- 面板需要支持收起、恢复、宽度调整和任务状态反馈。
- Agent 回答必须继续区分内部语料、联网证据和模型推断。

### 证据边界

- **用户明确选择**：统一的上下文 Agent 侧边面板。
- **现有实现事实**：当前已有 Agent 侧栏，但入口层级、状态反馈、上下文传递和稳定性仍需优化。
- **待原型决策**：不同屏幕宽度下采用侧栏、全屏还是底部面板，不在此阶段锁死。

## 决策 8：整体视觉气质

### 已确认选择

**A：现代编辑型研究工作台。**

整体视觉结合专业研究简报与现代知识工具：使用温和中性色、克制的琥珀色品牌强调和高可读的无衬线正文；等宽字体仅用于日期、分数、代码和技术元数据。

### 产品含义

- 视觉目标是可信、清晰和适合长时间阅读，而不是模拟终端或堆叠企业仪表盘。
- 品牌色只强调关键操作、选择状态和重要信号，避免全页面高饱和竞争。
- 图表必须服务于具体趋势问题，不能替代证据和文本解释。
- 深色模式与浅色模式共享同一语义色彩系统，不分别维护两套视觉逻辑。

### 明确排除

- 不继续以大量等宽字体和命令行视觉作为默认界面。
- 不以尚未验证的趋势分数堆砌大屏式指标卡。
- 不通过完整 React/Tailwind 重写来换取视觉更新，优先渐进重构现有页面。

## 决策 9：默认信息密度

### 已确认选择

**A：标准密度 + 渐进展开。**

首页趋势卡片展示核心结论、代表证据和关键元数据；完整摘要、时间线与更多来源进入详情视图。完整选题表格继续提供紧凑、标准和舒展三档阅读密度，默认使用标准。

### 产品含义

- 渐进披露不等于删除、隐藏或重新生成原始摘要。
- 摘要内容保持原始数据合同，UI 只控制不同层级的展示方式。
- 短摘要不出现没有实际作用的展开按钮。
- 熟练用户可以提高表格密度，但该偏好不强迫所有新用户接受高密度页面。

### 证据边界

- **用户明确选择**：标准密度与渐进披露。
- **历史问题证据**：此前摘要折叠逻辑曾造成空摘要和无效按钮，因此新的展示层必须与摘要生产、存储逻辑解耦，并加入回归测试。
- **待验证假设**：默认卡片截取长度和表格标准行高需通过真实内容原型确定，不在决策文档中硬编码。

## 决策 10：动效强度

### 已确认选择

**A：克制的功能性动效。**

动效只用于解释状态变化，包括 Agent 思考与工具调用状态、搜索加载进度、面板开合、条目精确定位和短暂高亮。

### 产品含义

- Agent 保留“思考中”提示，并用轻微、低干扰的呼吸或位移动效表示仍在运行。
- 长任务需要阶段性状态文案，不能只靠循环动画掩盖真实等待。
- 所有关键操作在关闭动效后仍可理解和完成。
- 遵循 `prefers-reduced-motion`，不使用持续大幅移动、强制视差或装饰性转场。

### 证据边界

- **用户明确选择**：功能性、克制动效。
- **历史问题证据**：Agent 曾长时间只显示“思考中”，用户无法区分运行与卡死。
- **AI 设计判断**：状态文本、超时处理和流式反馈是主要解决方案，动效只是辅助反馈。

## 决策 11：桌面端与移动端优先级

### 已确认选择

**A：桌面研究工作台优先，移动端保证核心路径。**

桌面端完整支持趋势详情、多栏证据、可调 Agent 面板和高效表格；移动端首阶段保证趋势浏览、全局搜索、条目阅读和 Agent 问答可用，高级多栏研究能力按移动设备特点后续优化。

### 产品含义

- 移动端不是桌面布局的等比例缩小版。
- 共享数据合同、路由、搜索结果和证据语义，允许交互容器不同。
- 发布门槛包含移动端核心路径可用，不能以“桌面优先”为由完全放弃移动浏览。
- 首轮 UI 重构不追求所有高级功能在两端同时达到完全同等形态。

## 待最终确认的共享理解

1. 产品定位：趋势研究工作台，而非日报阅读器或聊天机器人。
2. 首页首屏：今日摘要和 3–5 个重点趋势。
3. 趋势口径：至少两条相互支持的证据；单一证据标为新兴信号。
4. 趋势详情：解释聚合逻辑，并提供日报词条、外部原文和上下文 Agent 三条路径。
5. 搜索：默认全库、支持筛选、模糊词透明归一、结果落到具体条目。
6. Agent：统一、常驻、上下文感知的研究助手。
7. 视觉：现代编辑型研究工作台，标准密度、渐进披露、功能性动效。
8. 设备：桌面完整研究体验优先，移动端保证四条核心路径。

## 实施边界

- 上述决策是产品目标和验收约束，不锁死具体组件、CSS 技术或页面容器。
- 侧栏与独立页面、搜索库、趋势聚合算法等工程选择必须通过原型或 benchmark 决定。
- 按产品恢复路线图，先修复 GitHub Actions 数据事实链路，再建立条目合同与搜索，随后修复 RAG，最后实施 UI 重构。
