# 事件抽取诊断集与密封盲测集计划

## 目的

在开发结构化语义抽取方案前，再用新日期复核规则抽取器的失败分布，同时保留一组未泄漏答案的最终验证资产。

## 数据角色

| 数据 | 日期 | 数量 | 用途 | 答案可见性 |
|---|---|---:|---|---|
| 新诊断集 | 2026-08-07 | 12 | 定位规则抽取失败类型 | 本阶段可见 |
| 最终密封盲测集 | 2026-08-08 | 16 | 新方案冻结后的最终判断 | 冻结前不可见 |

两组均从 `digests/search-index.json` 的独立原子条目中选取，覆盖第一方新闻、第三方新闻、研究、教程/开发内容、产品/仓库列表与普通配置内容。样本不能只选择带明显 `launch/tutorial` 关键词的容易案例。

## 标签合同

采用 `event-contract-v2`：

- `content_kind`
- `source_role`
- `event_type`
- `subject_entity_ids`
- `mentioned_entity_ids`

以下是源事实透传校验，不属于语义抽取能力：

- `publication_date`
- `temporal_confidence`

另标记 `importance_label` 和 `expected_tier`，用于计算非新闻误入率和后续热门动态产品测试。

## 隔离要求

- 标签 Agent 不读取 `rag/event_extraction.py`、历史预测结果或旧标签。
- 诊断集和密封盲测集由不同隔离 Agent 标注。
- 主执行 Agent 本阶段可以打开诊断标签，但不得读取密封盲测标签正文。
- 密封盲测资产只公开数据集 ID、样本数、来源/内容分层统计和 SHA-256。
- 新方案、Prompt 和阈值冻结后，才允许一次性运行最终盲测。

## 本阶段输出

1. 新诊断集及规则基线结果；
2. 密封盲测集和公开 manifest；
3. 规则抽取器失败类型统计；
4. 独立监管 Agent 的标签质量与数据泄漏审查。

本阶段不修改生产 ingestion，不写 ChromaDB/Neo4j，不重建索引。
