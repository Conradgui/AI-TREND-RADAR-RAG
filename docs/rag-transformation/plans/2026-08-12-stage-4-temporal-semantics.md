# Stage 4 计划：统一时间语义

日期：2026-08-12

## 为什么现在只做这一件事

Stage 3 已让“最近”过滤真正下传到底层检索，但当前过滤字段 `date` 实际表示日报收录日期。后来收录的旧文章仍可能被回答为“最新动态”。这不是 Top K 或 Prompt 能修复的问题，而是语料模型缺少明确时间语义。

## 目标数据契约

每个 DailyCorpusItem 明确区分：

- `publication_date`：原始内容正式发布的日期；
- `ingested_at`：系统第一次把内容写入规范化语料的时间；
- `observed_at`：某次热度、分数或状态观测发生的时间；
- `report_date`：条目被收录进哪一天的日报。

## 最小执行顺序

1. 只读盘点原始 `publishedAt` 等字段的真实格式与异常比例。
2. 先为时间解析和缺失降级写失败测试。
3. 在规范化边界产出四类时间字段，不修改原始内容身份和 ATR 编号。
4. lexical、vector、Graph Observation 读取同一时间契约。
5. “最近发布”优先按 `publication_date`；缺失时显式降级为 `report_date` 并记录 trace。
6. 用 5 条小样验证：新发布、旧文新收录、缺失发布时间、异常日期、重复观测。

## 本阶段不做

- 不扩张实体注册表；
- 不调整向量模型或 RRF 权重；
- 不建立正式 P/R/F1 宣称；
- 不重写 Web UI；
- 不同时优化 20 秒检索性能。

## Stage Gate

- 旧文新收录不能被无提示地称为“最新发布”；
- 缺失 publication_date 不得伪造；
- 同一 content_id 的多次 observed_at 保留纵向趋势；
- ATR 编号和现有条目跳转不变；
- 独立监管同时审查产品表述和代码契约。
