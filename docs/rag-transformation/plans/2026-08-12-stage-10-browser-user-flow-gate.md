# Stage 10：浏览器用户流程 Gate

日期：2026-08-12
状态：执行中

## 目标

用真实运行页面和端到端测试验证侧边栏搜索流程，而不是仅凭源码判断功能完成；只修复实际复现的阻断项。

## 当前证据

- 真实页面中时间、来源、分类三个筛选均已启用；来源有 20 个选项，分类有 5 个选项。
- 近 7 天筛选得到 203 条；近 7 天 + OpenAI + 模型与技术突破得到 2 条，结果元数据符合筛选条件。
- `open ai` 被识别为 OpenAI，并能进入独立 ATR 条目详情；详情包含摘要和原始来源链接。
- Playwright 5 条用户路径中 4 条通过；旧书签在详情、日报和浏览器历史之间切换时失败。

## 根因与最小修复

`loadReport()` 发起异步 Markdown 请求后没有验证当前路由。用户在请求完成前后退到条目详情时，旧日报响应仍会覆盖详情内容。修复是在成功和失败响应落屏前检查 `currentKey`，过期请求直接退出。

## 不做

- 不重写已经通过真实验证的筛选逻辑。
- 不扩大为搜索排序、标题改写或 UI 视觉重构。
- 不删除 legacy ID 兼容层。

## Stage Gate

1. 失败的 legacy 浏览器测试转绿。
2. 5 条 item-search E2E 全部通过。
3. 真实页面再次验证组合筛选与 ATR 详情跳转。
4. 质量监管 Agent 同时审查产品流程和 Stage 9 架构接线。
