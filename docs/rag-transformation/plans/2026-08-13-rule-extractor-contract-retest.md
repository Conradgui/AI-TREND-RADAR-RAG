# 规则事件抽取器合同校准复测

## 决策问题

历史 0 分究竟来自抽取能力不足，还是来自盲测标签与运行时事件合同不一致？

## 已确认事实

- 抽取器已完整执行，历史结果中的 `extractor_sha256` 与当时代码一致。
- 抽取器从未被 `ingest`、索引或服务端引用，因此 Stage Gate 阻止的是生产接入，不是离线运行。
- 盲测把 `first_party_news` 等“内容类型 + 来源角色”写在同一字段，而运行时使用 `news_event` 等另一套枚举；原始 0 分不能直接代表内容分类能力。

## 本轮边界

- 公开接口：`extract_event_fields(document)` 与 `evaluate_predictions(documents, annotations)`。
- 先统一 `content_kind`、`source_role`、粗粒度 `event_type` 合同，再评分。
- `publication_date`、日期来源等源事实以规范语料为准，不允许规则覆盖。
- 只运行离线校准复测；不写 ChromaDB、Neo4j，不重建正式索引。
- 原 8 条盲测已被主流程读取，本轮只能称合同校准集；若结果达到门槛，另选新日期做真正盲测。

## 通过标准

- 合同归一化测试通过；旧枚举可明确映射到新枚举。
- 输出原始历史分与合同校准后的新分，不覆盖历史证据。
- 若 `content_kind < 0.85`、主体识别 `< 0.80` 或提及实体 `< 0.75`，规则路线仍不得接入生产。
