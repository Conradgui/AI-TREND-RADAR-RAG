# Stage 7：侧边栏搜索筛选用户流程

## 目标

让时间、来源和分类筛选在索引加载前、加载后以及无关键词浏览三种状态下，都给用户明确、可验证的反馈。

## 诊断结论

- 当前筛选计算逻辑已经可用：来源与分类选项会在索引加载后生成，时间及组合筛选会改变结果。
- 历史故障缺少浏览器回归门禁；静态源码断言无法证明用户真的能操作。
- 索引加载期间三个下拉框仍表现为可操作，但来源与分类只有默认项，用户会理解为“没有列表 / 点击无反应”。

## 最小变更

1. 索引加载前禁用三个筛选控件，并保留“条目索引准备中”状态。
2. 索引成功后启用控件；失败时保持禁用并显示失败原因。
3. 新增静态页面专用 Playwright 配置，避免前端测试被 FastAPI 冷启动阻塞。
4. 新增端到端测试，覆盖加载态、选项生成和无关键词组合筛选。
5. 条目详情使用 ATR 身份从搜索索引恢复，不再被尚未同步的日报目录错误覆盖；普通日报路由仍受 manifest 约束。

## 不做

- 不重写搜索排名。
- 不改变 Search Document 数据契约。
- 不修改 RAG 检索或 Graph 模型。

## Stage Gate

- 定向 E2E 测试通过。
- 现有 item-search E2E 全部通过。
- 在运行中的 Web UI 手动复核筛选流程。
- 质量监管 Agent 同时审查代码逻辑与用户流程。
