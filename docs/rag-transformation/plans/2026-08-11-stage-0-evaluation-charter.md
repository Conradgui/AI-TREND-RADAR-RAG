# Stage 0：检索评估可信度章程

- 日期：2026-08-11
- 状态：提案，等待产品优先级确认
- 上位依据：ADR-0003、ADR-0004、RAG Evolution Playbook 独立适配复盘
- 本阶段不做：业务代码重构、正式索引重建、Graph schema 扩展、Prompt 改写、真实 LLM 批量调用

## 1. 为什么先做这一阶段

当前低分同时包含两种信号：检索系统真实缺陷，以及评估标签/任务契约不完整造成的噪声。如果直接修改语料、召回器或 Graph，结果即使变化也无法可靠归因。

Stage 0 的产品目标不是“做出一份看起来完整的数据集”，而是建立一把能回答以下问题的尺子：

> 某次改动是否让用户更容易找到正确条目、发现可靠趋势，并在证据不足时得到诚实回答？

## 2. 评估对象与优先级提案

第一轮只覆盖三类高价值行为：

1. `trend_discovery`：回答“最近有什么热门趋势”，是产品核心价值；
2. `item_navigation`：按标题或唯一 ID 找到具体条目，是可控性和 UI 深链的基础；
3. `evidence_sufficiency`：证据不足时不输出伪结论，是质量底线。

`relation_exploration`、完整 `claim_verification` 和复杂时间线暂不进入首轮评分。原因不是它们不重要，而是当前图模型和标签契约尚未成立；过早评分会再次制造诊断样本冒充质量指标的问题。

## 3. 成本受控的四步法

### 0A：盘点现有 32 条问题

每条只做四选一：

- `retain`：标签和任务契约足以直接评分；
- `repair`：补少量标签后可评分；
- `diagnostic`：保留用于暴露缺口，但不进入总分；
- `retire`：问题定义或期望证据错误，停止使用。

输出是一张审计表，不运行 LLM，不访问生产 API。

### 0B：形成 12 条高置信校准集

建议构成：

- 4 条趋势发现；
- 4 条精确导航；
- 2 条证据研究；
- 2 条证据不足/拒答保护。

每条必须包含：任务类型、冻结语料快照、可回答性、相关条目、分级相关性、允许/禁止证据、评分 cutoff、人工复核状态。

### 0C：证明评估器“有辨别力”

不先测新架构，而是构造三个可预期的结果集：

- 明显正确排序；
- 目标条目被噪声挤到后面；
- 完全错误或应拒答却返回证据。

评估器必须给出严格递减的结果，并正确标识不可评分样本。若做不到，先修评估器，不进入数据管线改造。

### 0D：运行当前系统基线

只在冻结快照运行一次，保存按任务拆分的 P@K、R@K、MRR、NDCG、拒答正确率和诊断原因。不将跨任务宏平均 F1 作为唯一决策依据。

## 4. 两个深模块及其 interface

### Evaluation Dataset Auditor

```text
audit_evaluation_dataset(EvaluationDataset) -> DatasetAuditReport
```

隐藏任务契约检查、标签完整性、重复问题、指标上限、快照资格和可评分覆盖率。调用者只需提交数据集并读取审计结果。

### Retrieval Evaluation Runner

```text
evaluate_retrieval(EvaluationDataset, RetrievalAdapter) -> EvaluationReport
```

同一数据集可以接旧索引、影子原子索引和任务路由 adapter。这样后续 A/B 比较替换 adapter 即可，不为每种架构复制评估逻辑。

## 5. 首轮成功标准

- 12 条问题人工复核状态：100%；
- 每条正式评分问题的 relevant set 与评分方式完整：100%；
- 诊断样本不进入宏/微平均：100%；
- 三组可预期结果满足 `正确 > 降级 > 错误`：100%；
- 快照不匹配时禁止形成发布结论：100%；
- 运行不调用 DeepSeek，不修改正式索引；
- 产出能按任务解释，不只给一个总 F1。

## 6. 停止条件

满足以下任一条件即暂停，不继续扩大投入：

1. 现有语料无法为 12 条问题提供可复核 gold evidence；
2. 人工无法一致判断哪些条目相关；
3. 评估器无法区分明显正确与明显错误结果；
4. 快照身份无法固定；
5. 需要修改正式索引才能完成 Stage 0。

## 7. 后续决策

Stage 0 通过后，才执行单日报影子语料实验。届时比较四个 variant：旧混合索引、原子条目、原子条目加 lexical、原子条目加任务视图。

如果 12 条校准集不能区分这些 variant，不扩充到 20–30 条，也不进入 GraphRAG；先重新审查问题定义和相关性标签。
