## 发布顺序教训

Docker 的 `/app/digests` 是持久卷。镜像重建不会自动用镜像内文件覆盖该卷；如果先迁移卷内索引再重建容器，旧卷产物可能继续覆盖镜像视图。正确顺序固定为：

1. 构建并部署镜像；
2. 等待服务健康；
3. 备份运行产物；
4. 迁移持久卷索引；
5. 用真实浏览器验证。

本次运行索引备份位于容器 `/app/digests/search-index.pre-stage7.json`。
