## 根因复核

当前合同混合了两种不同任务：

1. **内容/事件抽取**：这是什么内容、发生了什么、谁是主体、提到了谁；
2. **重要动态准入**：它是否足够新、影响是否足够大、是否值得进入“重要动态”。

`unknown` 目前同时承担“没有事件”“证据不足”“不重要”三种含义，导致模型在普通产品调整、分析文章和信息不足时倾向全部退回 unknown。

## 独立监管结论

`BLOCK` 扩大到 20 条。监管复算与主结果一致，并发现三条产品语义边界需要冻结：

- `ATR-20260807-6E3EA0`：生物安全回退机制调整，不应标成 `product_launch`；按照既定产品标准，推荐不进入重要动态主榜。
- `ATR-20260807-7618A0`：Apple/OpenAI 争议属于真实近期事件，但现有摘要不足以单独证明影响规模；推荐保留新闻/诉讼事件身份，重要性进入待证据确认。
- `ATR-20260807-149D82`：Perforce 报告发布属于研究内容，但更适合作为趋势证据，不等于公司重要动态。

## 下一最小实验

仍使用同一 5 条，不新增样本、不接生产：

1. 将语义抽取与重要性判断拆成两个输出合同；
2. 第一层抽取 `content_kind/event_type/subjects/mentions`；
3. 第二层单独判断 `is_important_dynamic`，要求“明确的新近事件 + 可陈述的实质影响”；
4. 普通功能、配置、价格、机制调整默认不进入重要动态，除非有重大产品架构变化或广泛影响证据；
5. Prompt v2 只运行一次，达到门槛后才扩大到 20 条。
