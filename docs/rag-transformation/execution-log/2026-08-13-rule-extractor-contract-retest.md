# 规则事件抽取器合同校准复测记录

## 结论先行

历史整条正确率 0 并不是因为 Stage Gate 没让抽取器运行。抽取器已经执行并保存结果；Stage Gate 只阻止它写入正式库和索引。

历史 0 分包含两类原因：

1. **评分合同错位**：`first_party_news` 把内容类型和来源角色混在一个字段里，而运行时使用另一套枚举。
2. **规则能力不足**：开放世界主体和提及实体识别明显失败，不能靠枚举映射修复。

## 本轮改动

- 新增 `event-contract-v2`：把 `content_kind` 与 `source_role` 分开，并收敛粗粒度 `event_type`。
- 评分前把历史标签显式映射到统一合同；历史文件不覆盖。
- 发布日期和时间可信度改为直接读取规范语料中的源事实，不允许人工标签或规则猜测。
- 对 Product Hunt、GitHub Search、Hugging Face 增加通用 listing 主体候选规则。
- 仍保持影子运行：未连接 ingestion、ChromaDB 或 Neo4j。

## TDD 证据

- 最小实现完成：8 passed。

## Stage Gate 判断

`BLOCK` 规则抽取器接入正式库和索引。

合同错位解释了部分 0 分，但校准后仍远低于既定最低门槛：content kind 85%、subject 80%、mentioned 75%。尤其提及实体只有 12.5%，证明固定别名和关键词无法覆盖开放世界实体。

下一步不再扩充关键词表。保留规则层处理确定性事实与校验；语义字段转入“结构化 LLM 小样 + JSON Schema + 确定性校验 + needs_review”路线，再以全新日期做真正盲测。

## 独立监管复核

监管结论同样为 `BLOCK`。监管特别指出：发布日期和时间可信度的 100% 是源事实透传一致率，不是语义抽取能力；旧 0% 与合同 v2 的 12.5% 口径不同，不能包装成同口径性能提升。本记录已按该意见分离源事实与语义指标，并补充非新闻误入率。
