## 已定位的失败机制

1. **内容分类需要语境，不是单词命中。** “safeguards”“report”“build”等词在新闻、研究和开发内容里含义不同；关键词无法稳定判断内容性质。
2. **事件类型需要理解动作关系。** 中文争议新闻没有英文 `lawsuit/sues` 关键词就漏掉诉讼；普通开发文章又会因 `build` 被误判成教程。
3. **主体与提及不是实体存在性问题。** 规则能找到 OpenAI，却不能判断它是事件行动者、对象还是背景提及。
4. **开放世界实体无法靠固定别名覆盖。** 新模型、报告、组织、框架和产品持续出现，导致新日期提及实体主诊断为 0%。
5. **来源角色缺少结构化 provenance。** GitHub Search、Hugging Face 等是发现渠道，不一定是内容发布主体；仅看 `source` 字符串无法稳定判断第一方/第三方。
6. **人工标签也需要置信度。** 12 条中只有 5 条达到高置信，说明合同应允许 `needs_review`，而不是强迫所有记录得到精确语义标签。

## 架构判断

停止继续扩充关键词。规则层只保留：ATR ID、URL、来源、发布日期、日期 provenance、JSON Schema 与一致性校验。

下一阶段用 5 条开发样本验证结构化 LLM 只输出语义字段：`content_kind`、`event_type`、`subject_entity_ids`、`mentioned_entity_ids`。先做低成本冒烟测试；明显优于规则后再扩大到 20 条，最后才消耗 16 条密封盲测集。
